# Confluence レポート作成用プロンプト

以下を、Confluence ページを書く AI エージェントにそのまま渡す。

---

あなたは技術ブログの編集者です。以下の「実験データ」だけを根拠に、Cursor・Claude・Genspark の比較レポートを Confluence ページ用に書いてください。

## 書き方のルール

- 日本語、です・ます調。結論を冒頭に置く
- 見出しと表を使い、Confluence にそのまま貼れる Markdown で出力する
- 実験データにない数値・事実・感想は書かない。足りない部分は `FIXME:` で始まる一文を置き、何を埋めるべきかを書く
- 所要時間などの数値は表にまとめる
- 画像・スクリーンショットを貼る位置には `FIXME: 画像（○○のスクリーンショット）` と書く
- 各ツールの良し悪しは、記録された事実（時間・要件充足・挙動）から言えることに留める。見た目の評価は筆者が後で入れるので `FIXME` にする

## ページ構成

1. 結論（3〜5行。現時点のデータで言えることだけ。Genspark の LP・スライドが未完である旨を書く）
2. 実験の目的とルール
3. 実験条件（ツール・プラン・モデル・設定）
4. 題材ごとの結果（01〜04。各題材に「結果の表」「ツールごとの所見」「成果物へのリンク」）
5. 横断して見えた違い（作り方・自己検証の深さ・確認の質問・文脈の引き継ぎ）
6. 実験中に起きたトラブルと対策
7. 用途別のおすすめ（`FIXME: 全題材が揃ってから確定` と注記したうえで仮案を書く）
8. 付録: プロンプト全文、リンク集

## 実験データ

### 目的とルール
- 同じプロンプトを3ツールに渡し、成果物を比較する（2026-10-30 実施）
- 一発目の出力を v1、手直し後を final として保存。手直しは最大2回まで（今回は全題材で手直し0回）
- 評価: 客観指標（所要時間・手直し回数・そのまま動いたか・要件充足数）＋見た目の ◎○△（筆者の主観）
- 題材は4つ。03 と 04 は各ツールが 02 で自作したキャラを使う
- 成果物リポジトリ: https://github.com/kaki-org/ai-agent-comparison
- 比較一覧（GitHub Pages）: https://kaki-org.github.io/ai-agent-comparison/
- 各成果物: `https://kaki-org.github.io/ai-agent-comparison/{claude|cursor|genspark}/{01-tetris|02-kaki-character|03-landing-page|04-slides}/final/`
- 詳細な記録: リポジトリの `{ツール}/{題材}/log.md`

### プロンプト（全ツール共通）
- 01 テトリス:「シンプルなテトリスを作ってください。」＋要件3点（ブラウザで開くだけの単一 HTML・外部ライブラリなし／7種類のブロック・回転・ライン消去・スコア・ゲームオーバー／キーボード操作）
- 02 柿キャラ:「かわいい柿のゆるキャラの画像を作ってください。」＋要件3点（ゆるキャラ風で親しみやすい表情／名前と一言プロフィール／形式は問わない）
- 03 紹介 LP:「前の題材で作った柿のゆるキャラ（画像）を紹介するランディングページを作ってください。」＋要件3点（ブラウザで開ける HTML／キャラ紹介・プロフィール・柿の魅力のセクション／スマホで崩れない）
- 04 スライド:「前の題材で作った柿のゆるキャラ（画像）を案内役にして、柿の魅力を紹介するスライド資料を作ってください。」＋要件3点（5枚程度／表紙にキャラ／形式は問わない）
- 画像の渡し方: Claude・Cursor は作業フォルダに画像を置きファイル名で指定。Genspark は画像を添付

### 横断して見えた違い（記録からの事実）
- 速さ: Claude が全題材で最速。Cursor は実機確認に時間をかけ、テトリスで約23分
- 自己検証: Claude は軽く確認して即修正、Cursor はブラウザ操作を伴う徹底確認、Genspark は途中で利用者に確認の質問をする
- 画像: Claude は画像生成を使わずコードで描く。Cursor・Genspark は画像生成
- 文脈の引き継ぎ: 名前を画像内に文字で入れた Claude は後工程で名前を維持できた。Cursor は名前がぶれた（ぽて柿→ポテガキ）
- 返答の言語: Claude は 01〜03 の最後の返答が英語、04 は日本語。Cursor は日本語

### トラブルと対策
- Cursor の LP 1回目: 「前の題材」を探して上位フォルダを検索し、Claude の LP を全文読んでいたため不採用。作業フォルダを他ツールと分離して取り直した
- Cursor が確認用に立てたローカルサーバーを止め損ねて残っていた（1回目の LP）
- Claude の LP: 筆者のプロンプト貼り間違いで2回やり直し（結果は不採用・比較には影響なし）
- Genspark: 実行途中の質問に筆者が気づかず待ち時間が発生
